# GodotCascade 0.8.0

GodotCascade 0.8.0 focuses on measured fine-grained reactivity and honest platform evidence while retaining source-format version 1 and the Godot 4.7 minimum.

## Install

Download `godot-cascade-0.8.0.zip`, extract it at the root of a Godot project so `addons/godot_cascade/plugin.cfg` exists, then enable **GodotCascade** under **Project → Project Settings → Plugins**.

## Highlights

- Retained binding and dependency indexes route named scalar and repeated-item invalidations directly to matching native controls while preserving debugger trace semantics.
- Same-identity keyed `Array` reorders can move and refresh existing rows without constructing a Repeat candidate. Conditions, nested Repeats, virtual windows, replaced item identities, changed keys, focus contracts, and structural bindings deliberately use the validated candidate fallback.
- The pinned deployment-queue comparison executes equivalent GodotCascade and GTML workflows, captures both native endpoints, verifies diagnostics and retained identity, and records complete-operation timings without presenting them as frame time.
- A side-by-side platform fixture compares Cascade text adapters with plain Godot `LineEdit` and `TextEdit` controls. Record creation, validation, and exact cross-platform closure rules prevent missing manual service evidence from becoming a pass.
- An external-evaluator protocol and structured response template make the remaining real-project validation gate concrete without fabricating community feedback.
- CI now exercises eleven native suites, including the certification fixture, on the full Linux gate and the minimum/current Linux, Windows, and macOS smoke matrix.

## Evidence and limits

The [deployment-queue comparison](../artifacts/godotcascade-vs-gtml-deployment-queue.md) preserves the original slow Cascade baseline and a post-optimization rerun. Retained routing removes the identified full-tree/candidate taxes, but GTML remains materially faster for the measured fine-grained updates. These are synchronous batch totals on one machine, not per-frame measurements or a general throughput ranking.

The retained reorder path is intentionally narrow. It requires a nonvirtual `Array`, unchanged unique keys and item identities, one stable row root, and no conditional, nested Repeat, focus-contract, or rebuild-dependent structure. Anything outside that proof falls back to atomic candidate reconciliation.

Headless desktop CI proves that the side-by-side fixture loads and both halves remain native and writable. It does not certify clipboard services, active IME composition, touch selection, virtual keyboards, or screen readers. Follow the [manual platform protocol](../platform-certification.md) and keep the roadmap gate open until real records pass its closure validator.
